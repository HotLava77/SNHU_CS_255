Module Eight Portfolio Reflection

This repository contains my Business Requirements Document from Project One and my System Design Document from Project Two for the DriverPass system. These artifacts demonstrate my ability to gather requirements from a client interview and translate those requirements into a structured system design using UML modeling techniques.

The DriverPass project was based on an interview with Liam, the owner of a driver training company. He wanted a cloud-based system that would help students better prepare for their DMV driving exams. The system needed to support online practice tests, lesson scheduling, secure payment processing, and administrative reporting. The overall goal was to replace manual processes with a centralized platform that could improve student pass rates while remaining secure and scalable.

One area I believe I did particularly well was organizing and separating functional and nonfunctional requirements in the Business Requirements Document. Clearly defining system behavior alongside performance, security, and scalability expectations made the transition to system design much more structured. In the System Design Document, I also ensured that each UML diagram served a clear purpose. The use case diagram identified system roles and interactions, the activity diagrams modeled workflows, the sequence diagram clarified message flow between components, and the class diagram defined the structural relationships within the system. Together, these models provided both behavioral and structural perspectives of the system.

If I were to revise one part of the project, I would expand the user experience aspect of the design. While the technical and architectural components are well documented, adding basic interface mockups or more detailed user journey explanations would make the design more concrete and user-centered. This would strengthen the connection between requirements and implementation.

In interpreting the client’s needs, I focused not only on what was directly stated but also on what was implied. The client emphasized cloud deployment and improved training outcomes, which led me to design a system with secure authentication, role-based access control, automated scheduling validation, and scalable infrastructure. Considering user needs is critical in system design because even a technically correct system can fail if it does not align with how users actually interact with it. Designing around user workflows and expectations increases usability and long-term success.

My approach to designing software begins with understanding the problem and clearly defining requirements before considering implementation details. I rely on process modeling to understand workflows and object modeling to define structure and responsibilities. I use sequence diagrams to validate system interactions and ensure proper ordering of events. In the future, I would incorporate more iterative stakeholder feedback and apply traceability techniques to ensure that every requirement is reflected in the final system design.

This project reflects my growth in systems analysis and structured design thinking. Over the course of the term, I developed a stronger understanding of how requirements, modeling, security considerations, and architecture all work together to create a complete and functional system.
